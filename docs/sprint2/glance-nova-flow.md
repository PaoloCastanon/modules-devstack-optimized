# Nova → Glance

Según [arquitectura de Nova](https://docs.openstack.org/nova/latest/admin/architecture) y el código desplegado SHA `247ea5d774305b688997f8df81c011b249eb793c`, `nova.image.glance.API()` es usado por Compute; `nova/compute/manager.py` consulta metadata de imagen y el driver libvirt prepara el disco, descargando/copiando desde Glance según backend y caché. El smoke test creó una instancia desde la imagen CirrOS activa y observó `BUILD → ACTIVE`; por tanto, el flujo integrado de arranque funcionó en este nodo. El baseline Glance probó `GET /v2/images/{id}` y el upload/download de una imagen temporal, con bytes idénticos. Neutron proporcionó la red.

La evidencia está en [`boot-states.txt`](../../evidence/sprint2/tests/boot-states.txt), [`image-download.sha256.txt`](../../evidence/sprint2/glance/image-download.sha256.txt) y [`backend-audit.txt`](../../evidence/sprint2/glance/backend-audit.txt). La captura no contiene el request HTTP exacto de Nova hacia Glance ni la ruta de caché elegida; `diagrams/nova-glance-sequence.mmd` sigue siendo una descripción de diseño para ese nivel de detalle.
