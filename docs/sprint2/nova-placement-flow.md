# Nova → Placement

El código desplegado de Nova stable/2026.2 SHA `247ea5d774305b688997f8df81c011b249eb793c` muestra `nova/scheduler/manager.py` llamando `get_allocation_candidates`; `nova/scheduler/client/report.py` compone `GET /allocation_candidates?<resources.to_querystring()>` con `SAME_SUBTREE_VERSION='1.36'`. La respuesta incluye `allocation_requests` y `provider_summaries`. Scheduler filtra/pesa hosts y `claim_resources` solicita `PUT /allocations/{consumer_uuid}` usando la versión negociada; `nova-compute` publica inventario/traits mediante resource tracker. La petición lleva token de servicio Keystone, request ID y header de microversión según cliente HTTP. `CONSUMER_GENERATION_VERSION='1.28'` aparece en el cliente para operaciones de allocations. [Auditoría](../../evidence/sprint2/placement/upstream-source-audit.txt).

En el `server create` del 2026-10-02, la [traza real del scheduler](../../evidence/sprint2/nova/scheduler-placement.log) registró candidatos filtrados/pesados, el intento de reclamar recursos en Placement y la selección del host `tt-openstack-lab`. La [traza de Placement](../../evidence/sprint2/placement/nova-requests.log) muestra, con identidad `service nova`, `GET /allocation_candidates?limit=1000&resources=DISK_GB:1,MEMORY_MB:512,VCPU:1&root_required=OWNER_NOVA,!COMPUTE_STATUS_DISABLED` (HTTP 200, microversión 1.36), `GET /allocations/{instance}` (200, 1.28), `PUT /allocations/{instance}` (204, 1.36) y, al limpiar, `DELETE /allocations/{instance}` (204, 1.0). El [smoke test](../../evidence/sprint2/tests/boot-states.txt) pasó de `BUILD` a `ACTIVE`; el provider y su inventario quedaron capturados en `evidence/sprint2/tests/`. El baseline independiente de [`/allocation_candidates`](../../evidence/sprint2/placement/candidates.response.json) muestra los campos `allocation_requests` y `provider_summaries`, y [`inventories.response.json`](../../evidence/sprint2/placement/inventories.response.json) registra VCPU, memoria y disco disponibles. Los logs no incluyen el cuerpo exacto de la llamada interna de Nova; esa comparación más fina queda para Sprint 3.

Fuente complementaria: [Placement usage](https://docs.openstack.org/placement/latest/user/) y [Placement API](https://docs.openstack.org/api-ref/placement/).
