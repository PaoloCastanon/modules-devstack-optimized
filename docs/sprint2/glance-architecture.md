# Glance: arquitectura y servicio desplegado

Glance Image API v2 ofrece catálogo de metadatos y datos binarios. Keystone autentica con token y el catálogo expone tipo `image`; la política controla autorización. Las capas son API REST → dominio/controlador → DB de metadatos y `glance_store` para bytes. `Image` mantiene UUID, owner, status, visibility, formatos, tamaño, hashes, fechas y flags; `ImageProperty` e `ImageLocation` se relacionan con ella. Las tablas `images` e `image_locations` se comprobaron en MySQL.

En la VM, `POST /v2/images` creó metadatos en estado `queued`; `PUT /v2/images/{id}/file` subió bytes y la imagen pasó a `active`; `GET /v2/images/{id}/file` devolvió los mismos bytes y SHA256. PATCH actualizó metadatos y DELETE eliminó la imagen de prueba. El store configurado realmente es `/opt/stack/data/glance/images/`, con un archivo de la imagen CirrOS del laboratorio. La petición sin token a la lista devolvió 401; el baseline autenticado respondió correctamente. Una instancia arrancó desde CirrOS y llegó a `ACTIVE`, aunque no se capturó el request HTTP interno exacto de Nova a Glance.
