# Modelo Glance

Verificado en `glance/db/sqlalchemy/models.py` del SHA desplegado `a3e5f490b7a28b1161714c94acffe5308d24b567`; [auditoría upstream](../../evidence/sprint2/glance/upstream-source-audit.txt). Las tablas `images` e `image_locations` y la [configuración real del store](../../evidence/sprint2/glance/backend-audit.txt) se comprobaron en la VM.

**Metadata en DB:** `images.id` UUID/PK; `name`, `owner`, `status` no nulo, `visibility` (private/public/shared/community), `disk_format`, `container_format`, `size`, `virtual_size`, `checksum`, `os_hash_algo`, `os_hash_value`, `min_disk`, `min_ram`, `protected`, `os_hidden`, `created_at`, `updated_at`, `deleted_at`, `deleted`. `image_properties` tiene PK entera y `image_id` FK, nombre+valor y unique `(image_id,name)`; `image_locations` tiene PK entera, `image_id` FK, URI `value`, `meta_data`, `status`. `image_tags` y `image_members` existen en upstream; el mínimo Go implementará sólo lo exigido por el baseline/Nova.

**Datos binarios en image store:** bytes administrados por `glance_store` en `/opt/stack/data/glance/images/`. La DB guarda location, tamaño y hash, pero no el payload. En Go se propone un backend filesystem para este laboratorio con escritura temporal + rename atómico y checksum calculado. El baseline comprobó `queued`→`active`, download idéntico y borrado; `saving` y `killed` no se observaron como estados intermedios/errores y requieren fixtures adicionales.
