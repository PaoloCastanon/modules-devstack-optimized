# Arquitectura objetivo Go (Sprint 3+)

Dos procesos HTTP independientes: `cmd/placement` y `cmd/glance`. Cada uno configura listeners, logging estructurado y health check; no comparten dominio ni DB. `internal/placement/{api,service,model,repository}` separa negociación de microversiones/JSON, reglas de concurrencia y persistencia. `internal/glance/{api,service,model,repository,store}` separa metadata de bytes. `internal/{auth,config,middleware,logging}` reutiliza validación de token Keystone, configuración, request ID y errores HTTP, sin acoplar modelos. [Diagrama](diagrams/go-target-architecture.mmd).

Contratos de interfaces: service recibe identidad validada y request tipado; repository ofrece transacciones y control optimista de generation; store ofrece `Put/Get/Delete` streaming con hash. Los handlers son responsables de media types, status, microversiones y serialización; no contienen SQL. Configuración por archivo/entorno sin secretos en Git. Logs JSON con request ID y latencia, nunca token ni payload binario. Tests unitarios por dominio, API/compatibilidad con fixtures, integración con Nova y prueba end-to-end. La estructura definitiva se ajustará al baseline capturado, sin iniciar aún implementación RF03–RF10.
